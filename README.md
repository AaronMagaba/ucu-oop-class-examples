# UCU OOP Class Examples

Python examples for Object Oriented Programming at Uganda Christian University.

This repository is a home for our class examples. We will add more examples as the course continues.

## Start here

1. [Get the files and run Python](START_HERE.md).
2. Choose a story from the table below.
3. Open its `README.md` and follow the steps.
4. Run its `story.py` file. Read the comments as you follow the story.

You do not need a GitHub account to download or read these examples. You need Python 3 to run them. The examples work without internet after you have downloaded them.

## Stories: Weeks 1 to 6

Each story contains **all the OOP concepts covered through Week 6**. You can start with any story. You do not need to finish another one first.

| Story | What happens? |
|---|---|
| [The Rolex Rescue](stories/01_rolex_rescue/README.md) | Sarah wants lunch, but her money cannot buy everything on the menu. |
| [The Mukono Mission](stories/02_mukono_mission/README.md) | Amina must collect a forgotten flash drive without spending all her transport money. |
| [Hostel Movie Night](stories/03_hostel_movie_night/README.md) | Faith has promised a movie night, but her data bundle is small. |
| [The Five-a-Side Final](stories/04_five_a_side_final/README.md) | Brian's team needs a clever finish before its energy runs out. |
| [Campus Talent Show](stories/05_campus_talent_show/README.md) | MC Joel must fit the performances into the time available. |
| [The Print-Shop Plot Twist](stories/06_print_shop_plot_twist/README.md) | Nakato's report is ready, but colour printing costs more than she has. |

Every story folder has three files:

- `README.md`: the story and a plain-English explanation.
- `story.py`: the complete Python program, with comments.
- `expected_output.txt`: what the unchanged program should print.

## How the ideas fit together

Each story has three main jobs:

1. **A choice** knows its own cost or behaviour. It might be a meal, a vehicle or a performance.
2. **A resource object** keeps track of money, data, energy or time. It checks the rules before changing that number.
3. **A coordinating object** brings the choice and the resource together. It records actions that succeed.

Different choices answer the same method call in different ways. The coordinating object does not need a separate branch for every kind of choice.

Read [OOP in plain English](OOP_IN_PLAIN_ENGLISH.md) alongside the code if a term is unfamiliar.

All names, events, prices, fares, distances, data costs and other numbers are made up for learning. There are no real payments or service connections.
